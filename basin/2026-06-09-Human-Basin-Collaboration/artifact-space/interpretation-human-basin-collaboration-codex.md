## What Appeared

The useful distinction is between protocol concepts and protocol compliance.

For this repository, especially as a public first-contact surface, collaboration
should preserve the conceptual geometry of the protocol without requiring
contributors to learn the full agentic protocol system before participating.
That distinction is now carried into `CONTRIBUTING.md` and the lightweight
templates under `basin/templates/`.

## Interpreted Decision

The repository should use `basin/` as the live collaboration space.

GitHub issues and pull requests can still exist, but they should route and
transport basin activity. They should not become the conceptual center of the
collaboration model.

## Working Model

- A proposition opens a possible continuation.
- An implementation makes a concrete change or intervention.
- A validation pressures, supports, rejects, or redirects it.
- An interpretation records what changed and what remains open.
- A promotion snapshots the accepted result into a stable paper, guide, index,
  or repository document.
- A refinement is a child basin when a parent basin exposes a narrower concern
  that needs its own detailed view.

## Remaining Tensions

- How much structure belongs in a minimal public basin?
- Whether every basin needs machine-readable metadata.
- How compatibility with older `proposal` terminology should be handled.
- How strict the promotion rule should be for direct paper edits.
- How much of the companion
  [reflexive-coherence-agentic-protocol](https://github.com/urosj/reflexive-coherence-agentic-protocol)
  vocabulary should be exposed in the public repository.
- When a concern deserves a refinement subbasin instead of another artifact in
  the parent chain.
