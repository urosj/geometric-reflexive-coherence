## Purpose

Implement the human-basin collaboration model by using lessons from the
companion
[reflexive-coherence-agentic-protocol](https://github.com/urosj/reflexive-coherence-agentic-protocol)
project to draft `CONTRIBUTING.md` and lightweight basin templates.

## Pressure Received

- The collaboration model should follow protocol concepts, but remain more open
  for humans.
- The repository needs practical files that contributors can use without first
  learning the full agentic protocol.
- The example basin should become a real demonstration of the contribution
  model rather than only a description of it.
- Implementation is a first-class protocol artifact; refinement should be a
  child basin or nested detailed view of a parent basin.

## Protocol Lessons Applied

- The protocol is a becoming support structure, not a compliance framework.
- Propositions orient; implementations make a concrete move.
- Validations and interpretations determine what actually appeared.
- Classification is not promotion.
- Supported expression and native capacity are different claim levels.
- Tensions are often discovered in use and should be recorded when they affect
  coherence or returnability.
- Compact communication is acceptable when links, boundaries, and claim limits
  remain visible.
- Stable subject slugs preserve returnability.

## Boundary

This does not import the full
[reflexive-coherence-agentic-protocol](https://github.com/urosj/reflexive-coherence-agentic-protocol)
protocol into this repository. It keeps the concepts and discards the heavier
machinery unless a basin becomes large, contested, or hard to re-enter.

Refinement is not treated as a normal parent-basin artifact. A refinement should
usually be a child basin under `refinements/` when a parent basin exposes a
narrower concern that needs its own detailed view.

## Remaining Tensions

- Whether promotion criteria should stay in `CONTRIBUTING.md` or move into a
  dedicated `basin/PROMOTION_CRITERIA.md`.
- How much template structure casual contributors will actually tolerate.
- Whether public GitHub PR and issue templates should use `proposition` as the
  visible term or translate it into more familiar language.
